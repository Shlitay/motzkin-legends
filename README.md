# Motzkin Legends — Prediction League

Private prediction game for a closed friend group. One manager (you) approves
participants each round after they pay via Paybox; participants predict the
score of 7 Israeli league matches per round and compete for a jackpot.

**Live:** https://motzkin-legends.vercel.app
**Repo:** https://github.com/Shlitay/motzkin-legends
**Supabase project:** `teuqvtarqminvutoozsx`
**Manager account:** `contact@shlitay.com` (must have `role = 'manager'` in the `users` table — see below if it ever needs re-setting)

## Status: real, deployed, and live-tested with real friends

This is **not** a mock-data demo anymore. Google login, onboarding, predictions,
payment-approval requests, manager approve/reject, and both leaderboards all
read and write the real Supabase database. As of this writing, 6 real
participants have registered and set round 1 predictions.

language toggle exists or is planned). `<html lang="he" dir="rtl">` in

## What's built and real

**Auth**
- Real Google OAuth via Supabase Auth (`src/lib/supabase/{client,server,middleware}.ts`, `src/proxy.ts` — Next.js 16 renamed `middleware.ts` → `proxy.ts`, same thing)
- `src/app/auth/callback/route.ts` exchanges the OAuth code, routes to `/onboarding` only if avatar/default-score are still unset on the profile row
- `proxy.ts` refreshes the session every request and gate-keeps `/manager/*` behind `role = 'manager'` — real server-side protection
- Google OAuth consent screen is **published** (not Testing mode) — any Google account can log in, no allow-listing needed
- `rls.sql` — Row Level Security on every table. Shared game data (rounds/matches/teams/scoring) is world-readable, manager-only-writable. Each user reads/writes only their own profile & predictions. A trigger blocks self-promotion to `role = 'manager'` through the app — that can only be set directly in SQL

**Pages** (`src/app/`), all wired to real data:
- `/` and `/manager/login` — real Google sign-in
- `/onboarding` — required first login: avatar + default score, writes to `users`
- `/home` — avatar/name (real). Stat cards (towards/points/hit for last round + season) are **still mock/placeholder** — not yet wired.
- **Round approval status** (`RoundApprovalStatus.tsx`) — self-contained (fetches its own open round + the current user's `round_participation` status), shown on `/home`, `/predictions`, `/leaderboard`, `/rules` (not `/manager` — the manager account doesn't participate). Inserts a real `round_participation` row when a participant clicks "שלחתי תשלום דרך Paybox." Status is color-coded: waiting = light orange (`border-draw`/`bg-draw`) with a clock icon, approved = light green (`border-brand`/`bg-brand`) with a checkmark icon, rejected = plain card with red text (not color-coded — wasn't asked for).
- **Round countdown** (`RoundCountdown.tsx`) — same 4 pages as the approval card, a live days/hours/minutes/seconds countdown to the open round's `deadline_at`, ticking every second. The countdown math itself is plain epoch-millisecond subtraction (always correct, timezone doesn't matter for a duration). The displayed kickoff clock time underneath, and `/predictions`' own deadline caption, both go through `formatIsraelDeadline()` (`src/lib/israelTime.ts`) — explicit `Intl.DateTimeFormat(..., { timeZone: "Asia/Jerusalem" })` conversion, not the viewer's own device timezone, since match kickoffs are inherently Israel-local (this replaced `/predictions`' old `formatDeadline`, which implicitly used the browser's local timezone — technically correct today since real participants are in Israel, but wrong if anyone ever checked from abroad).
- `/predictions` — reads real rounds/matches, reads/writes real `predictions` rows (upsert on submit). Generic across rounds (not hardcoded to round 1), though only round 1 exists so far. Round 1 fixtures: staggered 22.8-3.9.2026 (see migration 18 — originally seeded with one fake shared time). Each match row shows the team's real club crest (`TeamLogo`, 28px, `TEAM_LOGOS` in `mock-data.ts`) next to its name — **changed 2026-08-23**, replaced the earlier kit-color two-tone vertical bar (`TeamColorBar`/`TEAM_COLORS`, itself a replacement for small side-by-side dots before that). Crests are self-hosted PNGs in `public/team-logos/` (downloaded from football-logos.cc rather than hotlinked, so the app doesn't depend on their CDN staying up) — verified real/working with actual HTTP requests (not just trusting the fetched URLs) before downloading, since a fetch-summarized page can hallucinate plausible-looking asset URLs. **RTL gotcha (fixed 2026-08-23)**: the match row is a flex row that mirrors under the page's global RTL — `home_box` is DOM-first so it lands visually *rightmost*, `away_box` visually *leftmost*. The "תוצאה נוכחית" (current result, live matches only — see below for ended matches) line is plain text below the row, so it doesn't participate in that mirroring — its number order had to be set by hand to match (`{finalAwayScore}-{finalHomeScore}`, away first since that's the left side), not the source-order-looking `home-away`, which silently mismatched the row's actual left-right layout. Confirmed the box-to-side mapping with an isolated Playwright screenshot before picking the order, same as every other RTL fix this project has needed.
- **Match status** (added 2026-08-23): every match on `/predictions` is one of not-started / live / ended, computed client-side (`matchStatus()`, `src/lib/matchStatus.ts` — shared with `/leaderboard`'s round summary), no new column — `is_final` wins over the clock so a manager can end a match early. A 30s interval ticks the page's `now` state so a match flips from not-started to live on its own if the page is left open across kickoff, without needing a refresh (this app still has no realtime subscriptions anywhere). Not-started and live matches render via `MatchRow` — its own bordered card with a colored status pill (gray "טרם החל", green "בשידור חי" pulsing dot).
- **Ended-match card** (`EndedMatchCard`, redesigned 2026-08-24 from a Claude Design handoff — `design_handoff_prediction_result_card/Match Result Card.dc.html`, variant "1B"): a colored status rail + body (crests, the real final score large and centered, the user's prediction struck through on a miss) + a tinted points column, all pixel-matched from the handoff's exact spec (colors, type, spacing) rather than freehanded. Replaced an earlier gold/silver/gray tier-colored card. The color/label tier (exact hit / correct direction / miss) is derived by directly comparing the prediction to the actual score (`deriveOutcome()`) — mirroring `submit_match_result()`'s own exact/sign() comparison — rather than from the `points_earned` value, since `scoring_rules`' point amounts are manager-configurable and a value-based threshold would silently break if they change. **RTL note**: the card's root row (rail, body, points column) and its meta row (status text, outcome label) both mirror under the page's global RTL exactly like `MatchRow` above — verified directly against the handoff's raw HTML source (not just eyeballing a screenshot) after an initial pass had the status text and outcome label swapped. **Second RTL bug, fixed 2026-08-24**: the score itself (both the real score and the prediction line) is forced `dir="ltr"` — but that only fixes digit *shaping*, not which side it visually lands on. Same fix this codebase's previous card design already needed once for its own current-result line.

## Database migrations — run in this order on a fresh Supabase project

If ever setting this up again from scratch (or double-checking the current
project has everything applied), run these in the SQL editor in order:

1. `schema.sql` — full data model
2. `rls.sql` — Row Level Security policies
3. `seed-round1.sql` — creates the season, round 1, and its 7 matches
4. `fix-default-score-nullability.sql` — fixes a bug where default scores defaulted to `1` instead of `null`, which broke the "needs onboarding" check (already applied on the live project)
5. `add-avatar-to-season-stats.sql` — extends the `season_stats` view with `avatar` (already applied)
6. `add-nickname.sql` — adds the `nickname` column + extends `season_stats` with `display_name` (already applied, but worth double-checking if anything nickname-related ever errors)
7. `add-round-comments.sql` — creates the `round_comments` table + RLS for the `/home` discussion feature (already applied)
8. `add-lock-expired-rounds-function.sql` — creates `lock_expired_rounds()`, called lazily by the app (on `/home`, `/predictions`, `/leaderboard`, `/manager` load) to lock a round and fill per-match default scores once its deadline passes. It's a no-op for any round whose deadline hasn't passed yet, so applying it doesn't touch round 1's current data (already applied)
9. `add-news-strip.sql` — creates the singleton `news_strip` table + RLS for the manager-editable news ticker (already applied)
10. `add-round-comments-delete-policy.sql` — adds a `delete` RLS policy so a participant can delete their own round comment (to free up their one-per-round slot and post a new one). **Not yet applied** — run this before the "Delete" button on `/home` comments will work.
11. `add-hebrew-team-names.sql` — translates `teams.name` and round 1's existing `matches.home_team`/`away_team` text to Hebrew, as part of the Hebrew/RTL conversion. Pure `UPDATE` of existing rows' text (both tables are free text, not foreign-keyed), doesn't touch `predictions`/`round_participation` at all. **Applied** — `/predictions` shows Hebrew club names and matching crests.
12. `add-submit-match-result-function.sql` — creates `submit_match_result()`, called from `/manager`'s "תוצאות מחזור" screen once per match saved: records the score and recomputes every affected participant's `points_earned`/`total_points`/`exact_score_count`/`correct_result_count`/`rank` for the whole round in one go (already applied — **superseded by migration 15 below**, which changes this function's signature).
13. `add-match-is-final.sql` — adds `matches.is_final` (default `false`), tracking whether a score is live or final. **Applied** — verified 2026-08-26 via a direct PostgREST query against the live project (`select=id,is_final` returned `200 []`, not a column-not-found error); this note previously said "Not yet applied" but was stale.
14. `add-recompute-round-standings-function.sql` — extracts the aggregate/rank recompute out of `submit_match_result()` into a shared `recompute_round_standings(round_id)`, so `lock_expired_rounds()` can call the same logic. **Applied** — verified 2026-08-26 by calling the RPC live (got `204`, not a function-not-found error); this note previously said "Not yet applied" but was stale.
15. `update-lock-expired-rounds-seed-scores.sql` — extends `lock_expired_rounds()` (migration 8) to seed every still-unscored match to 0-0 the moment a round locks, and compute initial points/standings from that baseline. `create or replace`, same signature, safe over the existing function (already applied — **superseded by migration 17 below**, which fixes a gap in this version).
16. `update-submit-match-result-final-flag.sql` — extends `submit_match_result()` with a 4th parameter, `p_is_final`; the round's own `status` now follows its matches (`'finished'` once every match in the round is final, reverts to `'locked'` if a final gets unchecked). Drops the old 3-argument function first, since the signature changed (already applied).
17. `update-lock-expired-rounds-selfheal.sql` — fixes a gap in migration 15: the 0-0 seeding was nested inside the loop that only fires for rounds *transitioning* from `open` to `locked` at that exact moment, so round 1 (already locked days before migration 15 existed) never re-qualified and stayed unscored. Splits seeding into its own loop over any round with `status in ('locked', 'finished')` that still has unscored matches, regardless of when it locked — self-heals round 1 retroactively the next time this function runs (any page load). Superseded by migration 19 either way (see below), so whether this one specifically ran no longer matters.
18. `fix-round1-kickoff-times.sql` — data-only fix, not a schema change: round 1's `kickoff_at` was seeded with one fake time (22.8 20:00) for all 7 matches; real fixtures are staggered from 22.8 through 3.9. Corrects the 4 not-yet-finished matches' `kickoff_at` to their real kickoff times (source: 365scores.com, checked 2026-08-23) so the new not-started/live/ended status badges on `/predictions` (see below) are accurate. Home/away order was double-checked against the real fixture list and is already correct — untouched. **v2, corrected 2026-08-23**: v1 encoded the 365scores clock times as Israel-local (`+03:00`), but they're actually UTC — caught live when the Netanya-Sakhnin card showed 20:00 on 365scores against this file's 17:00, exactly the UTC+3 gap. v2 encodes them as literal UTC (`Z`) instead. Re-running v2 is safe even if v1 was already applied (plain `UPDATE` keyed on team names). **Applied.**
19. `update-lock-expired-rounds-per-match-kickoff.sql` — fixes a real bug in migrations 15/17's 0-0 seeding: it seeded *every* unscored match in a locked round to 0-0, with no check on that match's own `kickoff_at` — harmless while every match shared one fake kickoff time, but wrong now that migration 18 gives round 1 real staggered kickoffs (a match still days from actually starting would get force-seeded 0-0 and start contributing to standings). Gates the seeding loop, and the points update that follows it, on `kickoff_at <= now()` per match. **Supersedes migration 17 — safe to run directly even if 17 was never applied.** `recompute_round_standings()` already handles null `points_earned`/`home_score` correctly, so it didn't need changes. **Applied.**
20. `add-first-prediction-tiebreak.sql` — adds a third round-standings tiebreaker (added 2026-08-24): after total points and exact-hit count, whoever submitted their predictions earliest wins the tie. Uses `min(predictions.submitted_at)` per participant per round — no schema change needed, since `sendPrediction()` never includes `submitted_at` in its upsert payload, so PostgREST leaves it untouched on an edit; it's already "first created, not last updated" by construction. `create or replace` on `recompute_round_standings()`, same signature. **Applied.**
21. `fix-retroactive-early-seed-repair.sql` — one-time DATA repair (not a function change), added 2026-08-24 after a user reported the leaderboard showing 10 points for a round where the per-match breakdown only summed to 5. Root cause: migration 19 fixed `lock_expired_rounds()` going forward, but never cleaned up matches it had *already* force-seeded to 0-0 while still days from their real kickoff (a leftover from migrations 15/17's un-gated seeding) — one such match happened to match a participant's drawn prediction, scoring a spurious +5 that `total_points` (a cached sum) faithfully included. Nulls out `home_score`/`away_score`/`points_earned` for any match whose `kickoff_at` is still in the future (a real score can't exist yet, so any score present is leftover bad seeding), then calls `recompute_round_standings()` for every locked/finished round. Re-running is safe (a no-op once no future-kickoff match has a score). **Run this once, then check `/leaderboard`.**
22. `seed-round2.sql` — creates round 2's 7 matches (added 2026-08-24), same shape as `seed-round1.sql`. Round 1 was treated as a pilot and left unfinished on purpose (2 matches never played) rather than waited out — safe to do because `getCurrentRound()` (`src/lib/currentRound.ts`) picks the round with the highest `round_number` regardless of status, so every page cuts over to round 2 the moment this runs, with round 1 still browsable read-only via `/predictions`' prev/next picker. One consequence: `/manager`'s "תוצאות מחזור" results modal also uses `getCurrentRound()`, so it stops reaching round 1's matches once round 2 exists — finalizing those 2 leftover matches later would need direct SQL, not the modal. Fixture source: 365scores.com, checked 2026-08-24; kickoff times are literal UTC per migration 18's finding.
23. `add-backfill-late-approval-function.sql` — adds `backfill_late_approval(round_id, user_id)` (added 2026-08-26, found live during round 2). Fixes a real gap: `lock_expired_rounds()`'s one-time default-prediction fill only covers participants already `approved` at the moment a round locks — someone approved *after* that has zero `predictions` rows for the round, so their score isn't stale, it's genuinely never computed. This backfills their default prediction for any already-kicked-off match they're still missing one for, scores it, and recomputes. `src/app/manager/page.tsx`'s `approve()` now calls this after every approval (harmless no-op for an on-time approval), so a late approval self-heals immediately instead of needing a manual fix. **Run this once in the SQL editor before it'll work** — then, for anyone already approved late before this migration existed, toggle them to "המתנה" and back to "אישור" in `/manager` to trigger the backfill retroactively.

## Fixed: "current round" lookups broke once round 1 actually locked (2026-08-23)

Half the app (`NewsTicker`, `JackpotBadge`, `RoundCountdown`, `RoundApprovalStatus`, `/manager`'s participant lists, `/leaderboard`'s round-points table, `/home`'s round-comments section) independently queried `rounds` filtered to `.eq("status", "open")`, several using `.single()`. That's fine right up until a round's deadline actually passes and `lock_expired_rounds()` flips it to `'locked'` — which happened for real on 2026-08-23 (round 1's deadline was 22.8.2026 20:00) and broke `/manager` outright with a PostgREST "Cannot coerce the result to a single JSON object" error, while the other components just silently vanished (no crash, but the jackpot badge, countdown, approval card, etc. all disappeared exactly when the manager started entering results).

Fixed with one shared helper, `getCurrentRound()` in `src/lib/currentRound.ts` — the *latest round overall* (`order by round_number desc limit 1`), not filtered by status — now used by all seven of the above instead of each having its own ad-hoc query. `MatchResultsModal.tsx` already had this exact fix from when it was first built (see item 2 above); this pass generalized it everywhere else and removed the duplication. `predictions/page.tsx` was already unaffected — it fetches every round and falls back to the last one in the list when none is `'open'`.

## Live scoring: 0-0 kickoff baseline, current vs. final result (2026-08-23)

Real matches run live — they start at 0-0 and the manager updates the score as it happens, not just once at the end. Three linked changes (migrations 13–16 above):

- **0-0 baseline at kickoff**: `lock_expired_rounds()` seeds a still-unscored match to `0-0` (`is_final = false`) once *that match's own* `kickoff_at` has passed, and computes initial `predictions.points_earned`/standings from it — "empty" isn't a real state once a match has actually begun. Only touches matches with `home_score is null`, so a result the manager may have already entered pre-lock is never clobbered. **Fixed 2026-08-23** (migration 19): the original version gated this on the *round* locking, not each match's own kickoff — harmless when every match in round 1 shared one fake kickoff time, but wrong once migration 18 gave it real staggered kickoffs, since it would've force-seeded 0-0 for matches still days from starting the moment the round locked.
- **Current vs. final result**: `matches.is_final` (migration 13) drives a new "המשחק הסתיים" (the match ended) checkbox per row in `MatchResultsModal.tsx`, saved alongside the score via `submit_match_result()`'s new 4th parameter. On `/predictions`, the result line reads "תוצאה נוכחית" (current result) while `is_final = false`, "תוצאה סופית" (final result) once checked — same score-order fix from the previous commit applies to both.
- **Round auto-completion**: a round's own `status` now follows its matches — `submit_match_result()` sets it to `'finished'` once every match in the round is final, and reverts it to `'locked'` if a final gets unchecked again (fixing a mistake keeps the invariant true in both directions). Nothing else in the app branches on `'finished'` specifically — every "current round" lookup already goes through `getCurrentRound()` (see the fix above), which isn't filtered by status, so a finished round keeps displaying correctly everywhere.
- The aggregate/rank recompute (previously inlined in `submit_match_result()`) was extracted into a shared `recompute_round_standings(round_id)` (migration 14) so `lock_expired_rounds()` can call the identical logic instead of duplicating it.
